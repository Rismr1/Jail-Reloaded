JAIL-RELOADED - CONSOLE CONCEPT
Draft for review only. No startup banner or player-log changes implemented.

STARTUP LOGO
===========
Print once on startup. ASCII characters only, with optional console colors.
Use the server's normal timestamp, level, and [JailReloaded] prefix once per line.
The unprefixed message text would look like this:

       .-----------------------.
       |  |  |  |  |  |  |  | |
       |  |  |  | [o] |  |  | |
       |  |  |  |  |  |  |  | |
       '-----------------------'
          J A I L - R E L O A D E D
                     v1.0.0
          Originally By: graywolf336
       Fork By: Rismr1 | ImagineCraft Plugins

Logo idea: a small barred cell and lock above the plugin name. Keep the version
on its own line, followed by the original and fork credits. No large block of
ASCII lettering that wraps in a normal terminal.

Optional colors: gold name; yellow version; dark-gray bars; gray credits.
All messages must remain readable with colors disabled. No ANSI codes printed
as literal text. The banner does not repeat on /jail reload.

STARTUP STATUS
==============
The following lines appear after the logo (example values, not promises):

[13:45:10 INFO]: [JailReloaded] Server: Paper 26.3 | API baseline: 1.19
[13:45:10 INFO]: [JailReloaded] Storage: SQLite | jail3.sqlite
[13:45:10 INFO]: [JailReloaded] Loaded: 2 jails | 12 cells | 3 prisoners
[13:45:10 INFO]: [JailReloaded] Ready in 184 ms.

Use the actual server implementation and version at runtime. The API baseline
is separate from the detected server version. Print one storage result and one
load summary. Do not print every jail, SQL statement, or feature at INFO level.

If currency payments are enabled but unavailable:
[13:45:10 WARN]: [JailReloaded] Currency payments disabled: no economy provider. Check Vault and your economy plugin.

If a critical storage error prevents startup:
[13:45:10 ERROR]: [JailReloaded] Startup failed: cannot open SQLite storage. Check the data-folder permissions. Plugin disabled.

Never print Ready after a critical startup failure. Include technical details
in the associated error/debug output without exposing passwords or credentials.

PLAYER EVENTS
=============
One line for each completed action. Use stable labels and actual final values.
Log successful actions after completion, not while they are only being attempted.

[13:50:00 INFO]: [JailReloaded] JAILED | player=Alex | actor=Rismr1 | jail=spawn | cell=cell_01 | time=30m | reason="Griefing"
[13:52:00 INFO]: [JailReloaded] TRANSFERRED | player=Alex | actor=Rismr1 | from=spawn/cell_01 | to=spawn/cell_02
[13:55:00 INFO]: [JailReloaded] TIME_CHANGED | player=Alex | actor=Rismr1 | before=25m | after=35m
[13:56:00 INFO]: [JailReloaded] MUTED | player=Alex | actor=Rismr1
[14:00:00 INFO]: [JailReloaded] PAID | player=Alex | method=items | amount=5 | item=DIAMOND
[14:20:00 INFO]: [JailReloaded] RELEASED | player=Alex | cause=sentence_completed | jail=spawn | cell=cell_02
[14:21:00 INFO]: [JailReloaded] RELEASED | player=Steve | actor=CONSOLE | cause=admin_release | jail=spawn | cell=cell_03

For offline jailing, append state=offline_pending to JAILED. When the player
joins and is actually placed in jail, use:
[15:00:00 INFO]: [JailReloaded] PLACED | player=Alex | jail=spawn | cell=cell_01 | time=30m

Use actor=CONSOLE for console commands and cause=sentence_completed for timer
releases. Include an actor only when the code knows who performed the action;
do not invent attribution. Preserve full player UUIDs in DEBUG details so name
changes can be investigated without making every normal line excessively long.
Quote free-form reasons and remove embedded newlines/control characters.

Do not log normal sentence ticks, inventory slots, item NBT, every blocked click,
or every rejoin at INFO level. Never dump complete serialized inventories.

RELOAD AND SHUTDOWN
===================
[15:10:00 INFO]: [JailReloaded] Reload complete in 24 ms | active prisoners=3
[15:11:00 WARN]: [JailReloaded] Reload rejected: invalid config.yml near line 42. Fix the YAML and retry; active settings retained.
[15:12:00 WARN]: [JailReloaded] Reload failed: replacement storage unavailable. Previous storage connection retained.
[16:00:00 INFO]: [JailReloaded] Disabled | saved 2 jails and 3 prisoners.

Only report settings/connection/data retention when that specific failure path
actually guarantees it. Do not claim a successful save if storage reported an
error. Use the server's actual error level (SEVERE where applicable).

DEBUG EXAMPLES
==============
[15:13:00 INFO]: [JailReloaded] [DEBUG] CHEST_DENIED | player=Alex | uuid=<actual UUID> | cell=spawn/cell_02 | reason=not_assigned
[15:13:00 INFO]: [JailReloaded] [DEBUG] GEAR_CHANGE_DENIED | player=Alex | slot=HEAD | action=shift_click
[15:14:00 INFO]: [JailReloaded] [DEBUG] PROPERTY_RESTORED | player=Alex | slots=41 | codec=native_nbt

Only emit these when debugging is enabled. Rate-limit repeated denial messages
per player/action so held clicks or automation cannot flood the console.
Do not change gameplay permissions or protections to produce these logs.
